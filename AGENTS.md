# AGENTS.md

- Test with `bun test` (bun:test, real temp dirs; see tests/). No tsconfig: `bun run build` checks bundling, not types; delete the `index.js` artifact it leaves in the repo root (it is not committed). When TypeScript is available, typecheck the extension with `tsc --noEmit --module NodeNext --moduleResolution NodeNext --target ES2022 --skipLibCheck src/index.ts`.
- This directory is a live-installed extension: editing files here changes the user's running pi. Live-check features with `pi -p --session-dir <tmp> --session-id <id> --model <provider/model>` and read usage from the session JSONL (`.message.usage`).
- pi API facts learned the hard way (pi 0.84.x): at `before_agent_start`, `event.systemPrompt` is the base prompt without the skills section (pi appends it after handlers run), while `event.systemPromptOptions.skills` is the authoritative loaded set. `systemPromptOptions.selectedTools` does not reflect the prompt-build toolset (an exec_command-based toolset lists no "read" yet still renders skills) — do not gate on it. Extension `skillPaths` bypass `--no-skills`; honor the flag yourself.
- The pi-docs block template lives in pi's `dist/core/system-prompt.js`; when the strip stops matching after a pi update, update the anchors in `src/pi-docs.ts` and the `REAL_BLOCK` fixture in `tests/pi-docs.test.ts`.

- Residency checks must use public session APIs: `buildSessionContext(ctx.sessionManager.getBranch(), ctx.sessionManager.getLeafId())`, not an unexposed method on the readonly manager. Test lifecycle changes with a real in-memory `SessionManager`.
- Both `tool_result` and `message_end` are chained: later extensions can replace or delay a message before persistence. Confirm residency from final session context before suppression decisions, and keep reservations until a result is persisted or the run ends. Idle `sendMessage` rows can bypass extension `message_end` entirely.
